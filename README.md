# ESS Guard Client

React + TypeScript + Vite로 구현한 ESS 명령 탐지 웹 클라이언트입니다.
통합 감시·탐지 이력·시연 관리와 물리 검증의 R4 탐지 목록이 실제 서버 API에 연결됩니다. 서버 코드 변경은 없습니다.

## 최종 데스크톱 UI

`최종 UI 시안 자료`의 이미지를 기준으로 1440×900 관제 화면을 구현했습니다. 상단 도구 영역·왼쪽 탐색·하단 상태 표시줄은 고정되고 내용 영역만 스크롤합니다. 최소 화면 너비는 1120px이며 기존 React/Vite 실행 방식은 유지됩니다.

- 메인: 관제소 실루엣을 중심으로 좌우 ESS 배치, 통합 지표, 전력/수신 탐지 추이, 최근 경보.
- 사이트 상세: `#site/ESS-03/monitor` 등 설비별 경로. 개요·전 구간 감시·물리 검증·설비에 고정된 경보 로그.
- 경보 상세: `#incident/12` 등 이벤트별 경로. 서버 원문, 원본 명령, 동일 원인 탐지, 5단계 근거 검토. 검토 단계는 서버 재생과 별개입니다.
- 구성 설비는 `src/dashboard.ts`의 ESS-01–06이며 수신 이벤트의 추가 설비도 표시합니다. 구성 개수는 온라인/가동 설비 수가 아닙니다.
- 메인 SOC와 실제 출력은 `GET /api/telemetry/latest`의 설비별 최신 **처리된** 측정값을 우선 표시합니다. API가 404이고 이전 실측값이 없으면 **시뮬레이션 SOC**를 표시합니다. 잔량 막대는 0–100%에 비례하며, 미수신·조회 실패·0%를 구분합니다. 정격·통신 상태·계측 추이는 미제공입니다. 탐지 없음은 정상 판정이 아닙니다.
- 전역 경고: 어느 페이지에서든 좌측 상단의 붉은 경고 메시지 창·경고 배지를 표시합니다. 메시지 창의 배경색만 2.4초 주기로 부드럽게 변하고, 글자·버튼·ESS 카드 배경은 깜빡이지 않습니다. 창 닫기는 읽음 처리와 별개이며 새 경고가 수신되면 다시 표시합니다. 동작 줄이기 설정에서는 깜빡임을 생략합니다. 중복 SSE는 재알림하지 않으며, 미확인 경고는 목록 갱신으로 사라져도 읽음 처리 전까지 세션에 보관합니다. 읽음은 브라우저 sessionStorage에만 저장되며 서버의 사고 해제·판정 변경이 아닙니다.
- 배터리 게이지는 미확인 경고를 우선하여 CRITICAL 진한 빨강, HIGH 빨강, MEDIUM 노랑으로 표시합니다. 배터리를 포함한 ESS 카드 전체 배경은 수신한 탐지 이력의 최고 위험도에 따라 고정 색으로 표시하며, 읽음 처리로 이력 색을 지우지 않습니다. 경고가 없으면 20% 이하 잔량 부족, 미수신, 이전 수신값을 구분합니다. 초록은 잔량 표시이며 정상 판정이 아닙니다.
- 경보 로그의 위험도/건수는 서버 응답을 그대로 사용합니다. 규칙 버전이 없는 이력의 제목은 현재 규칙명으로 바꾸지 않습니다.

## 실행

Node.js 22.18 이상 권장 (검증 환경: Node.js 24.16).
PowerShell에서:

```powershell
cd C:\Users\benev\Documents\GitHub\ESS_Guard_Client
npm install
npm run dev
```

브라우저: http://127.0.0.1:5173/

기본 API 대상은 http://13.125.65.202:8080 입니다.
변경하려면 `.env.example`을 `.env.local`로 복사하고 `ESS_API_TARGET`을 수정한 뒤 Vite를 다시 시작합니다.

```dotenv
ESS_API_TARGET=http://13.125.65.202:8080
```

브라우저는 같은 출처의 `/api`만 호출합니다. Vite 개발/미리보기 프록시가 API 서버로 전달합니다.
대상 서버의 CORS 설정을 바꾸지 않도록 프록시에서 Host를 대상에 맞추고 Origin 헤더를 제거합니다.
개발 서버는 127.0.0.1에만 바인딩됩니다. 인증 기능을 추가한 구성에서는 인증·CSRF 정책에 맞춰 프록시를 다시 검토해야 합니다.

## 연결된 기능

- `GET /api/stats`: 서버 전체 처리·대기·탐지 집계, 위험도·규칙별 집계, 평가용 정답 라벨 건수.
- 선택적 `GET /api/telemetry/latest` 호환 조회: 현재 서버는 미지원입니다. 앱 실행 시 404가 확인되면 반복 조회를 중단하고 시뮬레이션으로 표시합니다. 서버 코드를 추가하거나 변경하지 않습니다. 지원하는 서버에 연결한 경우에만 반환된 SOC·출력·시각을 표시하고, 오류 시 이전 값임을 표시합니다.
- SOC 시뮬레이션은 설비별 최신 탐지에 따라 R1 방향 반전, R2 변화 속도 증가, R3 반복 방향 전환, R4 불규칙 변화의 가속 시연을 수행합니다. 탐지가 없는 설비는 기본 충·방전 흐름을 보여 주며 정상 판정을 의미하지 않습니다. 수치는 0–100% 범위에서 부드럽게 변하고 화면에 ‘가상 SOC’로 표시합니다. 메인의 가상 출력 합계와 사이트의 계획·명령·실제(모의)·SOC 그래프는 동일한 500 kWh·120배 가속 모델을 사용합니다. 첫 1시간은 생성된 시나리오이며 과거 실측을 복원한 것이 아닙니다. 과거 탐지 근거에는 가상값을 사용하지 않습니다. 서버 재생 정지와 독립적으로 동작하며, 새로 접속할 때 실측 API가 지원되면 실측을 우선 표시합니다.
- `GET /api/events?limit=200`: 최근 이벤트, 이벤트 행 선택, 원본 명령 ID 상세, 수신 범위 내 필터·페이지·원인별(명령/측정값) 그룹.
- `GET /api/stream`: 이름이 지정된 `detection`·`reset` 이벤트, ID 중복 제거, 재연결 시 목록 재조회.
- `POST /api/replay/start`, `stop`, `reset`: 시연 관리의 시작·정지·초기화 버튼.
- 통계와 목록을 3초마다 조회하므로 탐지가 없는 명령의 처리 진행도 갱신됩니다.
- 요청 실패 시 마지막 정상 데이터를 유지하고 오류 및 마지막 조회 시각을 표시합니다. 목 데이터로 전환하지 않습니다.

**시연 관리의 버튼은 실제 공용 서버를 변경합니다.**
초기화는 전체 탐지 결과를 지우고 모든 명령·측정값을 처리 대기로 바꾸며 재생을 정지합니다.
확인 창을 거쳐 실행하고, 초기화 후 자동으로 시작하지 않습니다.

## 현재 API에 따른 제한

- 전체 명령 목록·명령 상세 조회 API가 없습니다. 탐지 이벤트에 포함된 원본 명령 필드만 표시합니다.
- 명령 발생 시각, 개별 처리 상태, 개별 정답 라벨은 이벤트 응답에 없으므로 임의로 채우지 않습니다.
- 날짜·설비·위험도·규칙·클라이언트 검색과 페이지 이동은 **최근 최대 200건 안에서만** 동작합니다.
- 서버 전체 중복 제거 탐지 명령 수는 제공되지 않습니다. 목록의 명령 수와 전체 탐지 이벤트 수를 구분합니다.
- 재생은 명령과 측정값을 시간순으로 섞어 처리하지만, 통계의 진행률·정답 라벨 건수는 명령만 집계합니다. 명령 진행률 100%가 전체 재생 완료를 뜻하지 않습니다.
- 현재 재생 여부 조회 API가 없습니다. 재생 상태 표시는 마지막 제어 응답의 시각과 함께 표시합니다.
- SSE 서버는 초기 메시지·heartbeat·재전송 ID를 제공하지 않습니다. 첫 이벤트 전에는 연결 대기로 보일 수 있으며 주기 조회로 보완합니다.
- 시간대 없는 서버 탐지 시각은 배포 설정 기준 KST로 해석합니다. 시간대가 포함된 값도 KST로 변환합니다.
- 서버 a7e0ae3 기준 R1 계획 방향 불일치, R2 출력 편차, R3 잦은 방향 전환, R4 SOC 물리 불일치가 구현되어 있습니다. R5는 제거됐습니다. 규칙 화면은 정적 안내이며 정책 편집 기능은 없습니다.
- 기존 이력과 새 규칙이 같은 R1–R4 ID를 사용합니다. 이벤트에는 규칙 버전이 없어 이름을 임의로 붙이지 않고 원인 종류와 서버 메시지를 표시합니다. 구버전 이벤트의 빈 설비 ID는 미제공으로 유지합니다.
- commandLogId가 null인 측정값 이벤트도 표시합니다. telemetryId를 명령 ID로 바꾸지 않으며, 측정값 ID 클릭은 관련 탐지 상세를 엽니다.
- 물리 검증은 측정값 기반 R4 이벤트만 실시간 조회합니다. 실측 SOC·출력 시계열, 과거 원인 측정값, 정상/미평가/생략 결과 API는 미제공입니다. 시뮬레이션 그래프는 실제 탐지 근거로 사용하지 않습니다. 탐지 없음은 정상 판정이 아닙니다.
- R4의 서버 모델은 출력(kW)과 500 kWh 기준 SOC 변화량 비교입니다. 이전 전류(A)/용량(Ah) 예시와 다르며, 측정 시계열이나 잔차를 이벤트 메시지에서 추정하지 않습니다.
- 전 구간 감시는 기획 예시로 유지합니다. 온도·명령 응답·셀/팩 전압은 API 미제공 상태로 표시합니다.

전체 API 필드와 범위는 [API_CONTRACT.md](./API_CONTRACT.md)를 참고하세요.

## 검사 및 빌드

```powershell
npm test
npm run build
npm run preview
```

`npm test`는 응답 파싱·집계 구분·SSE 중복/재연결·초기화 중 오래된 응답 배제·제어 오류·요청 시간 초과와 필터 로직을 검증합니다.
테스트는 AWS 데이터를 변경하지 않습니다.

`dist`는 정적 웹 빌드입니다. Vite 프록시가 빌드 파일에 포함되지는 않습니다.
실제 배포 시 웹 호스트에서 `/api`를 서버로 전달하는 같은 출처 역방향 프록시가 필요합니다.
SSE 전달 경로의 버퍼링을 끄고 장시간 연결을 허용해야 합니다.
현재 단계에는 호스팅 배포나 데스크톱 앱 패키징이 포함되지 않습니다.

## AWS와 분리된 화면 검증

테스트 API는 메모리에만 데이터를 보관하며 외부 서버에 접속하지 않습니다.
아래 명령을 **서로 다른 PowerShell 터미널**에서 실행합니다.

터미널 1:

```powershell
node tests/fixtures/api-server.mjs
```

터미널 2:

```powershell
$env:ESS_API_TARGET='http://127.0.0.1:8181'
npm run dev -- --port 5183 --strictPort
```

http://127.0.0.1:5183/ 에서 행·명령 ID 클릭, 필터, 페이지 이동, 시작·정지·초기화, SSE를 확인합니다.
테스트 종료는 각 터미널에서 Ctrl+C입니다. 이 환경 변수는 해당 터미널에서 실행하는 프로세스에만 적용됩니다.
기본 5173 화면은 AWS 대상이므로 두 환경을 혼동하지 마세요.


## 서버팀 확인 사항

- 기존 DB가 비어 있지 않으면 CSV를 다시 적재하지 않습니다. 재생 reset은 새 시나리오로 데이터를 교체하지 않습니다. 최신 명령의 commandKw, 운전 계획, 측정 데이터가 같은 시나리오인지 확인해야 합니다.
- 전체 측정 처리 건수와 현재 재생 상태, 규칙 버전, 계획/명령 출력, 측정 시계열, 물리 계산 결과·생략 사유 조회 API가 필요합니다.
- 서버 파일 및 운영 데이터는 클라이언트 호환성 작업에서 변경하지 않았습니다.
